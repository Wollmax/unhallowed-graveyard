# Technical Specification (PRD): UniVault — Desktop Academic File & Deadline Manager

## 1. Общее описание проекта
**UniVault** — десктопное приложение для ОС Windows, объединяющее функции локального файлового менеджера и трекера учебных задач (практических, лабораторных и курсовых работ). 
Приложение синхронизирует базу данных задач (SQLite) с реальной структурой папок на жестком диске пользователя.

## 2. Рекомендуемый технический стек
* **Язык:** Python 3.11+
* **GUI Фреймворк:** PySide6 (Qt for Python) с темной темой (QDarkStyle / PyQtDarkTheme / Fluent Widgets) ИЛИ CustomTkinter. Предпочтительно PySide6 для полноценной поддержки Drag-and-Drop и системного трея.
* **База данных:** SQLite3 (хранение метаданных, дедлайнов, статусов, чек-листов).
* **Мониторинг файлов:** библиотека `watchdog` (отслеживание изменений в папках проекта в реальном времени).
* **Работа с документами:** `python-docx` (автозаполнение титульного листа в шаблонах отчетов), `shutil` / `pathlib` (управление файлами и архивация).
* **Уведомления:** `QSystemTrayIcon` (встроенный в Qt) или `winotify` для нативных Toast-уведомлений Windows.

## 3. Архитектура файловой системы (Core-механика)
При первом запуске пользователь выбирает корневую директорию (Root Workspace), например: `C:\UniVault_Workspace\`.
Приложение поддерживает строгую структуру директорий на диске:

Root_Workspace/
├── _Templates/                  # Глобальные шаблоны (.docx отчеты, титульники)
├── [Subject_Name]/              # Папка предмета (создается автоматически)
│   ├── _Materials/              # Общие материалы предмета (лекции, вопросы к экзамену)
│   ├── [Task_01_Title]/         # Папка конкретной практической работы
│   │   ├── 01_Task/             # Условия задачи, методички (.pdf, .docx, .txt)
│   │   ├── 02_Workspace/        # Исходный код, проекты, черновики (.py, .cs, .cpp, .blend)
│   │   └── 03_Submission/       # Готовые файлы на сдачу (финальный отчет, архив)

**Правило синхронизации:** 
Любой файл, помещенный в папки `01_Task`, `02_Workspace` или `03_Submission` (через интерфейс программы Drag-and-Drop или через стандартный Проводник Windows), автоматически отображается в карточке соответствующей практической работы в UI.

## 4. Схема базы данных (SQLite)

### Таблица `settings`
* `key` (TEXT PRIMARY KEY) — название настройки (`root_path`, `student_name`, `student_group`, `notify_days_before`).
* `value` (TEXT) — значение.

### Таблица `subjects` (Предметы)
* `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
* `name` (TEXT NOT NULL) — название предмета (например, "Структуры и алгоритмы обработки данных").
* `short_name` (TEXT) — краткий тег (например, "СИАОД").
* `teacher_name` (TEXT) — ФИО преподавателя.
* `exam_type` (TEXT) — тип аттестации ("Экзамен", "Зачет", "Диф. зачет").
* `folder_path` (TEXT NOT NULL) — относительный путь к папке предмета.
* `color_hex` (TEXT) — цвет маркера предмета в UI.

### Таблица `tasks` (Практические / Лабораторные работы)
* `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
* `subject_id` (INTEGER, FOREIGN KEY -> subjects.id ON DELETE CASCADE)
* `number` (INTEGER) — порядковый номер работы (ПР №1, ЛР №2).
* `type` (TEXT) — тип ("Практическая", "Лабораторная", "Курсовая", "Реферат").
* `title` (TEXT NOT NULL) — тема работы.
* `variant` (TEXT) — номер варианта (опционально).
* `status` (TEXT NOT NULL) — статус из фиксированного списка:
  - `NOT_STARTED` (Не начато - 0%)
  - `IN_PROGRESS` (В работе / Код - 30%)
  - `REPORTING` (Оформление отчета - 60%)
  - `WAIT_DEFENSE` (Ждет защиты / На проверке - 85%)
  - `REWORK` (На доработке / Правки - 50%)
  - `COMPLETED` (Сдано - 100%)
* `progress_percent` (INTEGER) — ручной или автоматический процент выполнения (0–100).
* `deadline_date` (TEXT, ISO8601 `YYYY-MM-DD HH:MM`) — дата и время дедлайна.
* `completed_date` (TEXT, ISO8601) — фактическая дата сдачи.
* `score` (REAL) — полученные баллы (опционально).
* `notes` (TEXT) — заметки, комментарии преподавателя, список правок.
* `folder_path` (TEXT NOT NULL) — относительный путь к папке работы.

### Таблица `subtasks` (Чек-лист внутри работы)
* `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
* `task_id` (INTEGER, FOREIGN KEY -> tasks.id ON DELETE CASCADE)
* `title` (TEXT NOT NULL) — текст подзадачи (например, "Написать код", "Сделать тесты", "Оформить выводы").
* `is_done` (INTEGER, 0 или 1) — статус выполнения.

## 5. Пользовательский интерфейс (UI / UX)

Главное окно разделено на 3 основные колонки (Master-Detail архитектура):

### Левая панель (Навигация и Предметы)
1. **Блок глобальных вкладок:**
   * `Дашборд (Горящие дедлайны)` — сводка всех активных работ по всем предметам, отсортированная по близости дедлайна.
   * `Календарь / Таймлайн` — сетка дедлайнов на месяц/неделю.
   * `Настройки и Шаблоны` — указание ФИО, группы, пути к Root-папке и загрузка `.docx` шаблона отчета.
2. **Список предметов:**
   * Отображает предметы с прогресс-баром (например, `Сдано 4 из 8`).
   * Кнопка `+ Добавить предмет`.

### Центральная панель (Список работ выбранного предмета или Дашборда)
1. **Фильтры и сортировка:** Фильтр по статусу (Скрыть сданные / Показать только горящие), поиск по названию.
2. **Карточки практических работ (List View):**
   * Цветовой индикатор дедлайна:
     - Красный: просрочено или осталось < 24 часов.
     - Оранжевый: осталось < 3 дней.
     - Зеленый/Серый: более 3 дней или статус `COMPLETED`.
   * Заголовок: `[ПР №3] Хеш-таблицы и коллизии`.
   * Бейдж статуса (выпадающий список для быстрой смены прямо из списка) + Прогресс-бар.
   * Дата дедлайна (`До 15.11, 23:59`).

### Правая панель (Инспектор / Детали выбранной работы)
Открывается при клике на практическую работу:
1. **Шапка:** Название, номер варианта, выбор дедлайна (DatePicker), смена статуса, ползунок прогресса (или авторасчет по чек-листу).
2. **Вкладка «Файлы» (3 секции с поддержкой Drag-and-Drop):**
   * *Условие (`01_Task`):* список файлов. Двойной клик открывает файл в стандартной программе ОС (`os.startfile`).
   * *Рабочие файлы (`02_Workspace`):* список исходников. Кнопка `Открыть папку в Проводнике` и `Открыть в VS Code / IDE`.
   * *На сдачу (`03_Submission`):* финальные файлы.
   * **Быстрые действия с файлами:**
     - Кнопка `Создать отчет по шаблону`: копирует `.docx` из `_Templates` в `03_Submission`, заменяя плейсхолдеры `{{SUBJECT}}`, `{{TASK_NUM}}`, `{{TASK_TITLE}}`, `{{STUDENT_NAME}}`, `{{GROUP}}` на данные работы, и переименовывает файл в `Отчет_ПР3_Фамилия_Группа.docx`.
     - Кнопка `Упаковать в ZIP`: архивирует содержимое `03_Submission` и копирует путь к архиву в буфер обмена.
3. **Вкладка «Чек-лист и Заметки»:**
   * Интерактивный список подзадач (при отметке галочек автоматически двигает `progress_percent`, если включена автосинхронизация).
   * Поле `Заметки / Правки` с поддержкой Markdown.

## 6. Система уведомлений и Фоновый режим
* При закрытии главного окна приложение сворачивается в системный трей Windows (`QSystemTrayIcon`), если эта опция включена.
* Фоновый таймер проверяет дедлайны при запуске и каждые 2 часа.
* Условия отправки системного уведомления (Windows Toast):
  1. До дедлайна осталось менее 72 часов (3 дня), а статус не `COMPLETED` и не `WAIT_DEFENSE`.
  2. До дедлайна осталось менее 24 часов.
  3. Дедлайн просрочен.
* По клику на уведомление разворачивается окно приложения с открытой карточкой нужной работы.

## 7. План поэтапной реализации (Для ИИ-агента в Antigravity)
Разработку необходимо вести итеративно по следующим шагам:
1. **Шаг 1 (Core & DB):** Создать модуль базы данных `database.py` (SQLite) и файловый менеджер `fs_manager.py`, который создает структуру папок на диске при добавлении предмета и задачи.
2. **Шаг 2 (Базовый UI):** Реализовать главное окно на PySide6 с левой панелью предметов, центральной панелью списка задач и диалоговыми окнами создания Предмета и Практической работы.
3. **Шаг 3 (Инспектор и Файлы):** Реализовать правую панель деталей задачи, отображение файлов из папок `01_Task`, `02_Workspace`, `03_Submission`, поддержку Drag-and-Drop файлов в эти зоны и открытие файлов по двойному клику.
4. **Шаг 4 (Автоматизация):** Добавить генератор `.docx` отчетов по шаблону, упаковку в `.zip` и чек-лист подзадач.
5. **Шаг 5 (Дашборд и Уведомления):** Реализовать сводный экран «Горящие дедлайны», цветовую индикацию сроков, сворачивание в трей и отправку Windows-уведомлений.
