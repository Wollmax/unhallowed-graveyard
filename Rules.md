# Project Rules for UniVault

## Architecture & Code Style
- Язык интерфейса приложения: Русский.
- Десктопное приложение: Python 3.11+, PySide6 (Qt). Это НЕ веб и НЕ Android (не применять правила Android/Jetpack Compose).
- Строго соблюдай модульность: НЕ пиши весь код в одном файле. Разделяй проект на:
  - `src/database.py` (только SQLite запросы и модели)
  - `src/fs_manager.py` (работа с папками ОС, архивация, генерация .docx)
  - `src/ui/` (главное окно, карточки, тема и диалоги PySide6)
  - `main.py` (точка входа)
- Все пути к файлам обрабатывай строго через `pathlib.Path`.
- Все изменения делай строго внутри текущей рабочей папки (`c:\Prog`), не копируй проект во внешние каталоги.

## Development & Execution Rules (Защита от зацикливания)
- Базовая реализация шагов 1-5 из `SPEC.md` уже выполнена.
- При получении запроса от пользователя выполняй конкретно запрошенное изменение точечно:
  1. Не перечитывай весь проект целиком — читай и редактируй только те модули, которые непосредственно относятся к задаче (например, `theme.py` для стилей, `dialogs.py` для новых диалогов).
  2. Не запускай долгие цепочки автономного тестирования со снятием скриншотов или анализом пикселей, если пользователь прямо об этом не просил.
  3. Делай минимально достаточные правки и сразу отдавай результат пользователю с кратким отчетом.
  4. После написания кода проверяй его через `python -m py_compile <файл>`.
